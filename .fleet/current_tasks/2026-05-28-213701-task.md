# Build Sentry MCP server automation infra

## Goal Contract

- **Outcome**: Sentry MCP installed and verified stable for Claude Code automation in interactive sessions. Automated patterns documented and validated with `claude -p` pipeline mode. Existing MCP inventory audited with rationalized lineup.
- **Why now**: The TriageDispatcher (Capsule CLI) relies on Sentry REST API for application-code enrichment. Sentry MCP enables interactive human-in-the-loop investigation ("find related errors", "investigate this issue") in Claude Code sessions. Before building automated ops (cron-based `claude -p` for daily checks), stability must be confirmed. The Firstory platform needs reliable Sentry access both for production triage and for agent-assisted investigation.
- **Authoritative context**: Read these files in order: (1) `../docs/operations/` directory — check for existing automation docs; (2) `.claude/settings.local.json` — current MCP/plugin config; (3) Capsule at `🧭-GROUND-TRUTH/2026-05-28-sentry-mcp-automation-infra/03-PLAN.md` — full step-by-step plan; (4) Capsule `scope.md` — scope contract with in/out scope, known risks, and acceptance criteria; (5) https://github.com/getsentry/sentry-mcp — official Sentry MCP repo for install/usage reference.
- **Constraints / Boundaries**: Read-only on document-mcp source code. Document automation patterns to `docs/operations/claude-code-automation.md` in document-mcp. Only install Sentry MCP via plugin marketplace (`claude plugin install sentry-mcp@sentry-mcp`), NOT via `claude mcp add`. Do not self-host Sentry MCP — use official hosted. Max time budget: 2 hours total. Do not touch Sentry native integrations (Sentry→Linear, Sentry→Vercel).
- **Non-goals**: Do NOT develop custom MCP servers. Do NOT build full CI/CD pipeline for Claude Code automation. Do NOT replace manual ops entirely. Do NOT install Sentry MCP via non-plugin method (would register as non-plugin and fail per GitHub issue #16371).
- **Failure / Recovery path**: If `claude plugin install` fails — verify plugin marketplace is accessible and `sentry-mcp@sentry-mcp` is the correct package spec; fall back to checking sentry-mcp GitHub releases for alternative install path. If Sentry auth fails in `claude -p` — verify `SENTRY_AUTH_TOKEN` env var is present; check Firstory Vercel project env vars. If `--chain` refactor task spawns with repeated failure — flag in 06-EXECUTION.md and escalate to human. If MCP tools do not appear after install — start a new interactive session (MCP loads at session start), or re-run `claude plugin install` with `--force`. If token overhead from 18 Sentry tools is excessive — document as a known issue in automation doc, do not attempt to fix in this task.
